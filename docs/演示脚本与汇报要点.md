# MiniAgentOS Coder 演示脚本与汇报要点

## 1. 演示目标

这次演示不要把系统讲成“又一个代码聊天框”。主线应当是：

```text
MiniAgentOS Coder 是一个本地 AgentOS 编程运行时。
它把模型输出变成受契约、上下文、工具、Guard、Sandbox、记忆和 Trace 管理的可审计运行。
```

面向导师或考官时，可以用一句话开场：

> 这个系统的重点不是让大模型直接改代码，而是把编程智能体放进一个可治理、可中断、可回放、可复用的本地运行时里。

## 2. 推荐演示路径

### Step 1: 打开本地项目

进入 Web 端后，先展示首屏的四步流程：

```text
打开项目 -> 准备运行 -> 持续调整 -> 验收结果
```

说明重点：

- 项目文件留在本地。
- 运行记录、审批、轨迹也保存在本机。
- 浏览器开发模式可以输入绝对路径；未来桌面模式使用系统文件夹选择器。

建议选择：

```text
examples/python-bugfix
```

### Step 2: 创建任务

在任务输入框中使用一个清楚的 Bugfix 任务：

```text
找出 calculator.add 测试失败的根本原因，修复实现，并运行相关测试验证。
```

先展示任务页的四类就绪状态：

- 模型是否已配置。
- 是否识别到测试命令。
- AgentPack 基线是否稳定。
- 是否识别到 AGENTS.md、OpenSpec、Skill 等开发协议。

再展示运行流程：

```text
上下文 -> 受控执行 -> 执行 -> 验证
```

说明重点：

- 用户不是直接把仓库全部塞给模型。
- 系统会先构建上下文包，再通过契约和治理策略约束动作。
- 任务可以直接开始，也可以先进入运行设置检查 Sandbox、工具策略和扩展能力。

### Step 3: 观察运行过程

运行开始后，重点展示三个区域：

1. 运行状态卡：当前阶段、下一步、最近事件。
2. AgentOS 控制平面：Contract、Context、Memory、Sandbox、Model Gate、Extensions。
3. 对话式运行控制条：运行中可以补充要求、纠正方向、要求先检查或要求验证。

可以现场补充一条指令：

```text
完成前请明确说明修改了哪个文件，并运行最小相关测试。
```

说明重点：

- 用户不用等待任务完全失败后重来。
- 新指令会在下一个安全边界生效。
- 如果当前有待审批动作，用户的补充要求可以触发重新规划。

### Step 4: 审批与验证

如果出现补丁审批，展示：

- 变更文件。
- diff 内容。
- 工具风险、effect 和审批原因。

批准后展示测试结果与完成验收：

- 是否有完成说明。
- 是否应用了项目变更。
- 是否记录了变更文件。
- 最新补丁后测试是否通过。

说明重点：

- 系统不只看模型说“完成了”，还要看运行时证据。
- 对 Bugfix/Feature/Spec，完成条件比 Chat/Review 更严格。

### Step 5: 查看控制面板

打开运行详情，依次展示：

- 上下文：预算健康度、Token 构成、保留/压缩/省略条目。
- 记忆：本次运行记忆、项目记忆、长期记忆。
- 治理：工具策略、Guard 检查、Sandbox 运行。
- 扩展：Skills、MCP、Hooks 的启用状态与运行证据。
- 轨迹回放：模型、工具、治理、扩展事件分布，并按时间回放。
- 运行报告：最终 summary、diff、测试、预算与 trace。

说明重点：

```text
AgentOS 不是一个抽象概念，而是落实为运行时控制面板。
```

### Step 6: 失败场景说明

如果演示中出现失败，不要回避，可以利用它展示系统特点：

- completion guard 会告诉你缺少什么证据。
- trace 会记录最后一个失败事件。
- recovery/checkpoint 可以从安全边界继续。
- follow-up composer 可以基于上一轮结果继续修复。

推荐解释：

```text
失败不是黑盒错误，而是受控运行的一部分：系统会保留失败原因、证据、检查点和下一步建议。
```

## 3. 系统亮点

### 3.1 AgentContract

每次运行前生成契约，约束：

- 允许和禁止的 effect。
- 最大模型调用、工具调用、步骤、Token 和时间。
- 每个工具的默认策略和本次覆盖策略。

讲法：

```text
模型提出动作，运行时根据 AgentContract 决定能不能执行。
```

### 3.2 上下文工程

系统不是简单拼接 prompt，而是管理：

- workspace scan。
- 相关文件和片段。
- AGENTS.md / OpenSpec / Skill 等协议上下文。
- Token 预算与组成分布。
- 上下文压缩和临界确认。

讲法：

```text
上下文是可解释、可压缩、可审计的运行资源。
```

### 3.3 工具治理

工具不是直接暴露给模型，而是统一经过：

```text
Action IR -> Tool Gateway -> Guard Pipeline -> Sandbox -> Trace
```

可以强调：

- 高风险工具需要审批。
- 路径、命令、预算、schema 都可检查。
- Sandbox 使用 argv 执行，不通过 shell 字符串。

### 3.4 扩展运行时

扩展能力包括：

- Skills：按任务模式推荐，运行中按需加载。
- MCP：发现外部工具后仍纳入 Tool Gateway 审批。
- Hooks：在 run/tool 生命周期中通过 Sandbox 执行。

讲法：

```text
扩展不是绕过运行时，而是被运行时接管。
```

### 3.5 Trace Replay

系统把运行变成事件流：

- 模型请求。
- 工具动作。
- 审批。
- Guard 决策。
- Sandbox 执行。
- 测试与完成验收。

讲法：

```text
运行结束后不是只有结果，而是可以复盘整个智能体行为。
```

## 4. 与普通 Coding Agent 的区别

| 普通代码助手 | MiniAgentOS Coder |
|---|---|
| 以聊天为中心 | 以受治理运行为中心 |
| 模型直接决定下一步 | 模型输出 Action IR，运行时检查后执行 |
| 上下文通常不可见 | 上下文预算、来源和压缩可见 |
| 工具权限不透明 | 工具 effect、审批、Guard、Sandbox 可见 |
| 失败后难复盘 | trace、report、checkpoint、replay 可追踪 |
| 扩展容易变成外挂 | Skills、MCP、Hooks 纳入统一运行时 |

## 5. 汇报时建议强调的创新点

1. 用 AgentContract 把智能体运行前约束显式化。
2. 用 AgentOS 控制平面把上下文、记忆、工具、模型、扩展统一展示。
3. 用安全边界支持运行中用户 steering，而不是只能启动或停止。
4. 用 completion guard 把“模型说完成”变成“证据满足后才完成”。
5. 用 trace replay 让失败和成功都能复盘。
6. 用 OpenSpec、AGENTS.md、SKILL.md 把开发过程规范化。

## 6. 演示前检查

```text
cd frontend
npm run check

cd ../backend
UV_CACHE_DIR=../.tmp-uv-cache uv run pytest
```

如果使用 Web 开发模式：

```text
# terminal 1
cd backend
uvicorn app.main:app --reload --env-file ../.env

# terminal 2
cd frontend
npm run dev
```

确认：

- DeepSeek API key 在根目录 `.env` 中，不在前端和 Git 中。
- 前端顶部模型状态为运行中或可用。
- 测试项目路径可打开。
- 运行失败时可以展示 trace、completion evidence 和 follow-up，而不是重启演示。
