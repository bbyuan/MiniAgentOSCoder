# 增加分层记忆与上下文压缩管理

## 背景

当前 Runtime 能构建基础 Context Pack，但压缩接口仍是占位实现，Context 中也没有真实内容和跨 Run 记忆。随着工具输出、修复轮次和项目知识增长，模型需要知道“当前应携带什么、为什么携带、何时压缩”；用户还需要控制哪些内容只属于本次 Run，哪些可沉淀到项目，哪些允许成为长期偏好。

## 变更内容

- 增加短期、项目级和长期三层记忆，并明确生命周期、写入权限和删除能力。
- Run 终止时自动生成脱敏的项目级执行记忆；长期记忆只能由用户确认后写入。
- 将可用记忆作为结构化 ContextItem 注入新 Run，并在 Trace、Checkpoint 和 Report 中保留引用。
- Context Pack 保存实际上下文内容、组成分布、阈值状态和压缩元数据。
- 增加 70%/85%/95% 分级压缩策略、手动压缩 API、临界确认和确定性摘要。
- Workbench 增加 Memory 管理视图，并将 Context 面板升级为可解释、可压缩的预算工作台。

## 能力影响

- `agent-runtime`：增加文件型 Memory Store、Run 记忆整合、Context Compactor、Trace/Checkpoint/Report 接入。
- `context-manager`：从静态 ID 列表升级为可参与模型请求的结构化内容与可审计压缩。
- `desktop-workbench`：增加记忆查看、编辑、删除、显式长期写入和上下文压缩控制。

## 不在本阶段

- 云端跨设备记忆同步、组织级共享知识和向量数据库。
- 使用另一个模型生成记忆摘要；本阶段使用可复现的结构化确定性摘要。
- 自动写入长期记忆或保存完整源码、密钥、环境变量值与大段原始日志。
