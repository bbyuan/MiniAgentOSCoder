# 建立完成度守卫与验收证据板

## 背景

当前运行循环允许模型通过 `finish` 宣告完成，并仅对“补丁后未成功测试”这一种情况做拦截。这不足以回答任务是否真的完成：评审任务不应产生写入，对话任务不应修改项目，代码任务需要变更与测试证据，失败或被拒绝的操作也不能被最终措辞掩盖。

## 变更内容

- 将 `finish` 从无条件终止动作升级为受 Completion Guard 检查的验收申请。
- 按 Bugfix、Feature、Review、Spec、Chat 五种模式生成确定性的验收条件。
- 验收失败时向模型返回结构化缺口并允许其在剩余预算内继续修正。
- 验收通过后才允许 Run 进入 `completed`，并保留每次评估的 Trace 事件。
- 将最终验收结果写入 Run API、SQLite 历史、运行报告和桌面结果页。
- 用结构化检查项表达“要求、状态、证据”，为后续 Benchmark、回放和消融实验复用。

## 能力影响

- `agent-runtime`：新增模式感知的完成度判定和拒绝续跑语义。
- `run-history`：持久化可查询、可比较的验收结果。
- `desktop-workbench`：新增运行前验收预期和终态证据板。

## 不在本阶段

- 使用另一个 LLM 充当主观裁判。
- 自动生成项目特有的业务验收用例。
- 跨项目排行榜和完整 Benchmark 数据集管理。
