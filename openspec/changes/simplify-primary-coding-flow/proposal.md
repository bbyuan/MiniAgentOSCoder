# 以任务为中心重构核心交互

## 背景

当前核心流程要求用户先选择任务模式、填写需求、分析任务、理解预检，再手动启动执行。运行后完整 Inspector 默认出现，进一步暴露 Context、Memory、Governance、Extensions、Recovery、Report 和 Trace 等内部模块。系统能力完整，但用户需要先理解 AgentOS 才能完成一次普通编码任务。

## 目标

将默认体验收敛为“打开项目、描述需求、开始任务、处理必要审批、查看结果”。AgentOS 能力继续工作，但只在影响决策时出现。

## 变更内容

- 主操作从“分析任务”改为“开始任务”，自动完成准备并立即执行。
- 将任务类型从五个大型选项收进紧凑选择器，保留模式能力但不占据页面主体。
- 提供次要的“检查运行设置”入口，供需要调整安全与扩展的用户进入。
- 设置分支不再展示预检能力清单，只展示任务摘要、模型状态和两个可编辑设置页面。
- 运行 Inspector 默认收起，通过“运行详情”按需打开；等待审批时自动打开。
- 项目语言、包管理器等识别结果不再作为主页面底部配置区展示。

## 不在本阶段

- 修改 Agent Loop、Completion Guard、Context、Memory、Governance 或 Extensions 后端能力。
- 删除运行证据和历史中心。
- 打包桌面安装程序。
