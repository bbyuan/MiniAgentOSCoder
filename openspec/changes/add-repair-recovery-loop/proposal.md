# 增加多轮修复与快照恢复闭环

## 背景

补丁审批闭环已经能保存写入前快照、应用补丁并执行测试，但测试失败后的行为仍缺少显式语义：界面无法区分首次执行与第几轮修复，用户也不能查看或恢复已保存的安全点。快照目前只是审计产物，还不是可操作的恢复能力。

## 变更内容

- 将测试失败作为结构化 Observation 交回同一 Agent Loop，记录修复轮次并要求后续补丁重新审批。
- 为修复循环增加由 AgentContract 步数和工具预算共同约束的终止边界，禁止脱离预算无限重试。
- 扩展 Checkpoint Store，列出检查点及其快照、目标文件和可恢复状态。
- 增加仅允许非活动 Run 调用的显式回滚 API，按快照清单恢复旧文件并移除该补丁新建的文件。
- 在 Trace 与 Artifacts 中记录修复开始、修复成功、回滚开始和回滚完成事件。
- 在 Workbench 增加 Recovery 标签页，展示恢复点并提供带确认步骤的回滚操作。

## 能力影响

- `agent-runtime`：增加可观测的多轮修复和恢复点查询。
- `tool-gateway`：Patch Pipeline 增加受路径守卫保护的快照恢复。
- `desktop-workbench`：增加检查点、修复轮次与手动回滚交互。

## 不在本阶段

- Daemon 进程重启后恢复正在执行的 Python 线程。
- 自动回滚测试失败的补丁。
- 合并多个恢复点、部分文件回滚或三方冲突解决。
