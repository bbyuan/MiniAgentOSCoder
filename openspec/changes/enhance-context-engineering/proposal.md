# 完善任务感知上下文工程

## 背景

当前 Runtime 会生成 Workspace Index，也能维护结构化 Context Pack，但新 Run 的初始上下文主要由任务、项目画像、计划和记忆组成。索引中的符号、导入关系、测试文件和代码片段尚未根据任务检索进入模型请求，`AGENTS.md` 也没有成为可执行的项目约束。这使 Context Manager 的可解释结构已经存在，但尚未形成真正的代码上下文选择能力。

## 变更内容

- 自动发现并加载工作区根目录及 `.agent/` 中的 `AGENTS.md`，将其作为受保护的项目规则加入 Context Pack。
- 根据用户任务、文件路径、符号、导入关系和测试关系，为 Workspace Index 中的代码片段评分并选取相关上下文。
- 为入选片段保存相关性分数、匹配词、代码范围和选择原因，供 Workbench 解释。
- 将已应用的当前补丁作为受保护的 `current_diff` 上下文项，确保后续测试与修复基于最新改动。
- 补齐 Workspace Index 的测试关系，并对索引读取失败采用可审计的安全降级。
- 修正规格中的 Bugfix 完成条件，允许“代码已符合要求且经检查和测试验证”的无补丁完成路径。

## 能力影响

- `context-manager`：增加项目规则发现、索引加载、任务相关性检索和当前补丁保护。
- `agent-runtime`：创建 Run 时使用工作区生成任务感知 Context Pack，补丁应用后刷新当前 Diff。
- `desktop-workbench`：复用现有 Context 面板展示新的来源、原因、范围和相关性元数据。

## 不在本阶段

- 外部向量数据库、云端知识库 RAG 和跨项目代码检索。
- 使用额外模型生成检索查询或摘要。
- IDE 级增量语法树索引；本阶段保持本地、确定性和可复现。
