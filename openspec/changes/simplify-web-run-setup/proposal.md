# 简化 Web 运行配置与信息层级

## 背景

当前任务页和运行前页面使用大量 8–10px 辅助文字，并将模型、Sandbox、上下文、Skills、MCP、Hooks、Completion Guard 与完整 Inspector 同时呈现。用户无法快速判断哪些必须手动配置、哪些由系统自动管理、哪些只是可选增强，也难以理解 Inspector 标签对应的功能。

## 变更内容

- 将运行前检查重组为“必须配置、自动管理、可选增强”三个明确层级。
- 唯一必须手动配置的模型 Provider 使用阻塞状态和直接操作呈现。
- 将 Sandbox、上下文和完成验收标记为自动管理，不要求用户逐项设置。
- 将 Skills、MCP 和 Hooks 标记为可选增强，展示启用数量但不阻塞启动。
- 默认隐藏完整 Inspector，仅在用户主动打开高级设置时展示。
- 提升任务页、运行前页面、结果摘要和 Inspector 的核心字号与行高。
- 使用更具体的 Inspector 标签，例如“安全策略”“检查点”“执行轨迹”。

## 能力影响

- `desktop-workbench`：调整 Web 与桌面共享前端的配置层级、渐进展示和排版。

## 不在本阶段

- 改变现有治理、扩展、上下文或模型 API。
- 删除任何高级能力。
- 生成新的桌面安装包；最终 Web 体验确认后统一打包。
