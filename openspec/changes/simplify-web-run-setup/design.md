# 设计

## 信息优先级

### 必须配置

只包含会阻止运行的项目。当前仅模型 Provider 属于这一层。未配置时显示明确的“需要配置”状态和配置按钮；已配置时显示模型名称与“已就绪”。

### 自动管理

包含正常情况下无需用户介入的系统能力：

- Sandbox：按默认安全 Profile 执行，用户可在高级设置中收紧。
- Context：准备任务时自动收集并受 Token 预算约束。
- Completion Guard：按任务模式自动验收，不作为手动开关。

### 可选增强

包含不影响基础运行的 Skills、MCP 与 Hooks。每项展示当前启用数量，全部为零也不显示警告。用户可主动打开高级设置进行调整。

## 渐进展示

Run 处于 planning 时，`workbenchLayout` 默认只有主画布，不渲染 Inspector。运行前页面提供一个“高级设置”入口；打开后才恢复双栏布局和 RuntimePanels。运行开始后仍按现有行为显示 Inspector，以便观察执行证据和处理审批。

## 排版

- 主体说明不小于 13px。
- 操作标签、状态和次要数据不小于 11px。
- 仅眉题和紧凑技术元数据允许 10px，不再使用 8px 或 9px 承载关键内容。
- 配置行使用稳定的图标、名称、状态和值布局，状态不只依赖颜色。
- 窄屏下配置行纵向排列，高级 Inspector 回到下方内容区。

## 命名

Inspector 标签使用用户目标命名：运行概览、提示上下文、智能体记忆、Skills / MCP、安全策略、检查点、运行报告、执行轨迹。名称本身表达用途，避免再堆叠教程式小字。
