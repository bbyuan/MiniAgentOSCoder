# 设计

## 核心原则

工作台不以“展示所有 AgentOS 模块”为首页目标，而以“让用户完成一次受治理的编码任务”为目标。上下文、记忆、扩展、治理和轨迹在与当前决策相关时出现，完整能力继续保留在 Inspector 中。

## 体验状态机

### 1. 未选择项目

页面中央展示产品主动作“打开代码项目”、最近项目和简短的本地运行说明。桌面端按钮打开系统目录选择器；浏览器端允许输入绝对路径。此状态不显示预算、Activity 或 Inspector。

### 2. 已选择项目，尚未准备

展示项目名称和路径、任务类型选择、任务输入器及可点击示例。主按钮文案为“分析任务”，说明该动作只创建 Run、收集上下文并生成契约，不会修改文件。

若模型尚未配置，此状态直接提供配置入口。桌面宿主将凭据保存到操作系统凭据管理器，启动 Daemon 时以进程环境注入；Workbench 不写入浏览器存储、项目文件或日志，Daemon 状态接口也不回传密钥。

### 3. Run 已准备

展示运行前检查：模型是否就绪、任务模式、Sandbox Profile、允许的 effects、已启用 Skill/MCP/Hook 数量和上下文预算。主按钮文案为“开始执行”，并提供返回修改任务的动作。

### 4. Run 执行中

主画布显示当前阶段、计划进度和实时 Activity。等待审批时，将 Approval 提升为主操作；Inspector 提供 Overview、Context、Memory、Governance、Extensions、Trace 等深入视图。

### 5. Run 终态

展示结果摘要、变更文件、测试状态和预算，提供查看报告、回放以及“新建任务”。错误与取消状态保留可理解的恢复入口。

## 项目选择

Tauri 桌面端通过官方 dialog plugin 选择单个目录。前端只接收选择结果并调用现有 `POST /projects/open`；Daemon 继续负责路径解析、项目画像和持久化。浏览器开发模式使用路径文本框，不模拟系统对话框。

最近项目复用 `GET /history/projects`，按最近运行时间展示。选择最近项目与系统选择目录进入同一项目打开流程，不维护第二套项目状态。

## 组件边界

- `ProjectLauncher`：未选择项目状态、目录选择、路径输入和最近项目。
- `TaskSetup`：任务类型、示例、输入和“分析任务”。
- `PreflightSummary`：准备态模型、治理、扩展与上下文摘要。
- `RunWorkspace`：执行态 Activity、指标、审批和 Inspector 编排。
- `CompletionSummary`：终态结果和下一步动作。

`Workbench` 继续拥有 API 与 SSE 状态，子组件只接收显式数据和回调，避免引入新的全局状态库。

## 桌面权限

只启用 dialog 的 `open` 权限。前端不获得任意文件读写权限，目录内容仍由 Daemon 在项目打开后按现有契约访问。

## 可访问性与响应式

- 主流程使用真实标题层级和步骤状态，不用教程弹窗遮挡界面。
- 任务类型使用单选式 segmented/list 控件，目录与运行命令使用明确文本按钮。
- 在小于 980px 时 Inspector 作为可切换下方面板；小于 680px 时项目与任务动作纵向排列。
- 所有状态不仅依赖颜色，并提供文字与图标。
