# 建立引导式编码工作台

## 背景

当前工作台把预算、Activity、Inspector 和任务输入同时放在首屏。首次使用者面对空面板、预填演示路径和两段式运行按钮，无法判断应该先选择项目、描述任务，还是配置运行时。核心能力虽然已经存在，但没有形成一条符合编码助手使用习惯的主路径。

## 变更内容

- 将工作台组织为“选择项目 -> 描述任务 -> 运行前检查 -> 执行与审阅 -> 结果”的渐进流程。
- 桌面端使用系统目录选择器打开项目，浏览器开发模式保留路径输入能力。
- 展示持久化运行目录中的最近项目，降低重复打开项目的成本。
- 提供可点击的任务类型和任务示例，但不向输入框注入伪造任务。
- 在空闲态隐藏预算、空 Activity 和完整 Inspector，只呈现当前动作所需内容。
- 准备完成后显示模型、模式、治理边界和扩展能力摘要，并明确“开始执行”。
- 运行开始后再展开实时活动与 Inspector，终态突出结果、测试和后续操作。

## 能力影响

- `desktop-workbench`：新增渐进式工作流、项目选择、最近项目和状态相关布局。
- `desktop-shell`：新增受限的系统目录选择能力。

## 不在本阶段

- 内置代码编辑器、完整终端模拟器或多窗口项目管理。
- 云端账号、跨设备项目同步和远程工作区。
- 自动修改用户项目，仍需经过现有 Run、Guard、Sandbox 和 Approval 流程。
